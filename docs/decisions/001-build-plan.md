# 001 — The pkstack build plan (ratified 2026-08-29)

pkstack = pstack's body (poteto-mode router, 23 playbooks, 21 principle leaves, the
multi-model review instruments, the prose discipline) + kstack's nervous system (the finding
ledger under Bennett's razor, the instantiated-lessons map, the verification sweep, the
close-unit self-improvement loop).

Ratified decisions of record (full rationale in the session's build-plan artifact):

1. **Standalone fork.** kstack stays untouched serving its consumers; pkstack carries the
   history forward. Vendor branch = pstack subtree-split with full history; merges are
   three-way with true ancestry.
2. **Three layers.** Additive (free forever) > patch set (enumerated in PATCHES.md, ~24
   files) > vendor (never edited directly).
3. **One ledger per repo — pkstack included.** Product and process lessons share each repo's
   single ledger. Exports queued at working repos' closes are pkstack's finding inbox;
   plugin-level lessons mint at pkstack maintenance closes, extensions citing repo:probe
   members. Plugin edits are approval-gated exports, never automatic loop output.
4. **The two razors reconciled.** One law — every shipped line traces to evidence. A fix
   ships on its runtime repro (smallest change, nothing more); a lesson/mechanism ships on
   its cited extension members, in its own commit; breadth with neither is belt-and-suspenders
   and does not ship. Heavy promotions queue with named triggers.
5. **The gate is toolbox, not flow.** external-review stays out of the playbooks; per-repo
   AGENTS.md owns policy; the non-author verifier is the default independence rung; the
   loop-health row records the verifier's model id verbatim so anchoring is measured.

   *Amendment, 2026-09-03.* The non-author round is the default independence rung **in** the
   playbooks, not merely available to them: it runs on a composed-on checkpoint inside a unit,
   and on a gated unit over the whole unit diff before the PR opens. The external gate is
   **unrouted toolbox** — kstack-init seeds no `scripts/external-review.sh`, and the gate runs
   only where a repo's own procedure file names it. The blind control is **driver-counted**
   from the ledger's loop-health rows, the `·fed` rows standing since the last `·blind` row;
   no script schedules it.
6. **Register/close split.** opening-a-pr registers a gated unit with a named close trigger;
   shipping's ceiling (stacks), the coordinator's wave boundary (orchestrate/autopilot), or
   the named trigger (solo) closes it. Fan-out hunters stay ledger-blind everywhere.
7. **Chasm guards.** A unit is its goal, not its playbook (re-route ⇒ re-classify at the same
   BASE); wire-check after every vendor merge; spine check with a one-time kstack-init offer;
   ship-half wires dormant solo are recorded as unvalidated; ceremony is wanted housekeeping,
   measured to stay lean, moved to subagents when heavy, never dropped.
