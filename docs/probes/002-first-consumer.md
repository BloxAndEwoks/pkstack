# Probe 002 — first-consumer findings (gi-project compliance worktree, 2026-08-30)

**Unit.** Maintenance mini-unit from pkstack's first real consumer session (gi-project
compliance-tool worktree). Transcript scan showed the switch's true shape: pkstack's ORGANS
crossed (premortem/simplify fired in the pkstack namespace; GATED classification and
design-package vocabulary took hold in probe 060) while the BODY stayed dormant — zero
poteto-mode entries, zero playbook-step copying, zero unit registration, no close trigger.

**Finding (one mechanism, two surfaces).** A mode ported to a host without a mode system is
dead unless its entry is re-based on the host's own invocation mechanism, at every layer that
routes work:
1. `poteto-mode` carried `disable-model-invocation: true` — correct in Cursor (the host
   applies modes; the `reminder:` key nudges), inert in Claude Code (no mode system, no
   reminder support): the model could never enter the mode itself.
2. `templates/AGENTS.template.md` — the procedure file kstack-init generates, the SOVEREIGN
   document every session obeys — never mentioned the router, so even a willing session was
   routed straight into the bare cadence. Every initialized repo would reproduce the gap.

**Fix (this commit).** The router is model-invocable with an explicit start-of-task trigger
and opt-out in its description; the template's Build Cadence now opens with the routing
contract (router classifies → playbook drives → register → close).

**Close note.** Single incident, two surfaces of one mechanism — recorded, not minted (razor;
same discipline as probe 001 C4). If a second porting-class member appears, the lesson mints
over both.
