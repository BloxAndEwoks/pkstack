### Feature

**You own the design. Plan, review, verify.** Delegate implementation; stay in the lead.

1. `how` over the affected subsystem.
2. Premortem the design package with the **premortem** skill. Its ledger-blind dives run first, then the driver's ledger walk leaves the implicated-lessons map in the probe. Then `architect` for parallel design exploration. Skipping stays as `architect skipped: <reason>`; do not fold the design decision silently into implementation.
3. Write the throughput checkpoint as four todo items. A dimension that genuinely does not apply (single file, no fan-out) keeps its item with `n/a: <reason>` rather than being dropped:
   - **Blocking first steps.** Gates run before fan-out.
   - **Independent workstreams.** Disjoint files, services, or layers parallelize. Shared writes serialize.
   - **Shared mutable state.** Default to splitting the target (the **separate-before-serializing-shared-state** principle skill). Serialize only for real invariants.
   - **Smallest safe decomposition.** If one worker is best, name why.
4. Delegate code-writing to a subagent using your configured feature model (default `grok-4.6-fast-xhigh`) with a specific scope (file paths, named data shape and its organizing structure per **principle-model-the-domain** — a state machine over scattered booleans, a table/registry over branching, a typed model over repeated shape assumptions, chosen before the delegate writes logic — and success criteria); review its diff yourself. The brief carries the design package's implicated-lessons annotations verbatim, so the delegate never re-walks the ledger itself. When the implementation admits multiple valid shapes (error handling, abstraction layer, test structure), delegate via the **arena** skill instead so the runners surface the alternatives and the cross-judge guards the pick. Mandatory: no skip-with-reason escape, and Laziness Protocol does not override it (the gain is review separation, not lines saved). The delegate owns the diff under the delegate contract in `agents/poteto-agent.md` and never spawns a review round of its own. A checkpoint is composed-on when it lands a migration, a boundary value type, a served contract, or a state transition that a later checkpoint in this same unit writes or reads. Every composed-on checkpoint takes one fresh-context non-author review round, fed the ledger, before the next checkpoint builds on it. A leaf checkpoint waits for step 5a instead. Comments per **Comments**. Surgical edits, re-ground against the source for upstream-derived files. Port shared-primitive improvements to all consumers and verify each. Commit liberally.
5. Verify on the matching surface through the repo's `verify-<project>` skill. Run its smoke first, then drive the unit's changed mapped features as their consumer meets them. A feature map found wrong runs the skill's MAINTAIN mode in the same sitting. A repo without the skill drives the surface directly and flags the missing skill as a gap. Targeted tests are the unit floor and never a substitute for the drive. "Inconclusive" or wrong-surface is not a pass; flag it. Every lesson the design package implicated gets its own named verification lane on that same real surface. The lanes are a floor under the surface checks, never a substitute for them.
   **5a.** Sweep the unit's diff (`BASE..head`) against the repo's finding ledger via the **verify-sweep** skill, in a neutral falsify/verify register. The package's implicated-lessons map is the work breakdown. A young or empty ledger falls back to the generic falsification classes in `skills/verify-sweep/references/seam-catalogue.md`. Every finding, from any review layer, lands in the probe's triage table with a `reachable` value of `real user today`, `crafted client`, `raw writer`, `operator`, or `not today`, evidenced at rung 4 or higher of the **blast-radius** evidence ladder (you ran it, or you reproduced it in the running app). A `real user today` finding is fixed by class before the PR opens. Every other reproduced finding is registered with a named trigger, and the unit is done when no real-user finding is open.
6. Rebase into small, ordered commits; stack follow-ups.
   Use the **sequence-verifiable-units** principle skill, building, verifying, and committing each small unit before the next.
7. If the design is contested, run one round of `interrogate` before shipping. On a gated unit this is also the non-author round over the whole unit diff, fed the ledger, before step 8.
   **7a.** Run **close-unit** when the unit's sweep landed findings. The unit's final review round has run by here, and the close comes before the PR opens.
8. Run **Opening a PR**.

Code-coupled work (one feature, one migration) goes to a single owner with the checkpoint inline; that owner fans out internally after the blocking phase. Parent-level fan-out is for slices that produce independent artifacts (audits, cross-subsystem investigations, competing experiments). Rewrite the checkpoint at phase boundaries; spawn a fresh owner rather than chaining interrupts.

**Reply:** what you built, what you chose and why, open decisions. Tables for design alternatives.
